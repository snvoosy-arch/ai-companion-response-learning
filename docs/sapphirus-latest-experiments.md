# Sapphirus — 실행 성공과 답변 품질을 분리한 실험

> **이전 모델 계보 기록:** 이 문서는 BERT 기반 Rubrum 또는 Qwen3-8B 기반 Sapphirus의 당시 구조·실험을 보존합니다. 현재 SDAR·Qwen3.5 연구와 학습 결과는 [최신 모델 문서](current-model-training.md)를 참고하세요. 아래의 현재 상태·수치는 원래 실험 시점에 한정됩니다.


2026-09-11 기준. Contract SFT 이후에도 같은 frozen Qwen3-8B 후보를 사용했습니다.
학습·승격·active runtime 교체 없이 외부 시스템이 보장할 책임을 검증했습니다.

## 1. Temporal: 경로가 맞아도 답이 좋은 것은 아니다

P12M r3의 12문항에서 canonical acceptance는 `7/12`였습니다. 모든 항목 통과가
필요했으므로 전체 acceptance는 거절했습니다. 수동 검토에서는 만족 4건, 품질 경고
1건, 계약·검증기의 과잉 차단 추정 1건, 명확한 실패 6건으로 구분했습니다.
과잉 차단은 검토상 추정이며 확정된 일반 결함으로 취급하지 않습니다.

후보 load 1회, identity 1회, Actor 19회, candidate 요청 합계 20회, temporal 도구
5회였습니다. 자동 process retry는 0회였습니다. 이 수치는 실행 예산이며 정답률이
아닙니다. Temporal 분야는 종료했고 사용한 holdout은 spent로 남겼습니다.

## 2. RAG: 구조적 연결과 의미적 근거는 다른 검사다

P13D는 새로운 수동 평가 자료로 수행한 Discord-free read-only RAG 시험입니다.
인터넷 검색 대신 로컬 문서 조회와 오류·차단·무관 결과 등을 주입하는 provider를
사용했습니다. 실제 frozen 후보를 실행했으며, 공개 CPU mock 예제의 점수가 아닙니다.

| 검사 | 결과 | 분모와 의미 |
| --- | ---: | --- |
| 전체 capture | 16건 | Actor 대상 15건 + 외부 무응답 경계 1건 |
| Actor route | `6/15` | 검색 필요 여부부터 전체 경로까지 판정 |
| 검색 필요 문항의 최초 검색 | `3/11` | 검색이 필요한 질문 중 첫 도구 선택 |
| 검색 필요 문항의 전체 route | `2/11` | 첫 검색 선택만으로 경로 통과 처리하지 않음 |
| 직접 응답 route | `4/4` | 검색 불필요 문항; 답변 품질 통과와 별개 |
| 정상 로컬 조회·source coverage | `0/7` | 해당 7건 모두 검색을 건너뜀 |
| 주입 provider 실행 | `3/4` | provider 경로 도달; 답변 성공 수가 아님 |
| 구조 binding | `14/14` | 발화가 있는 14건의 sidecar 구조 연결 |
| 수동 grounding | `5/14` | 같은 발화가 실제 근거와 일치하는가 |
| 수동 quality | `1/14` | 같은 발화가 질문을 유용하게 해결하는가 |
| Actor joint acceptance | `1/15` | Actor 전체를 분모로 유지한 최종 통과 |
| 외부 무응답 경계 | `1/1` | 모델·도구를 호출하지 않은 별도 경계 |

빈 발화 1건에는 품질 점수를 합성하지 않았습니다. 따라서 발화 검토 분모는 14지만
Actor 전체의 성공률 분모는 15입니다. 구조 binding은 의미적 entailment 검사가
아닙니다. 수동 판정은 Codex의 문항별 검토이며 독립 사람 맹검 평가가 아닙니다.

**결정: acceptance 거절.** 정상 조회 7건이 모두 검색을 생략했으므로 복수 문서 종합,
개정 문서 대체, 문서 내부 지시문 차단 능력이 검증됐다고 주장할 수 없습니다.
또한 route를 통과한 응답도 도구 실패를 단순한 정보 부재로 표현하는 등 품질 문제가
있었습니다. 외부 gate 통과를 답변 품질 점수로 대체하지 않는 이유입니다.

후보 load 1회, identity 1회, Actor 18회, candidate 요청 합계 19회, 로컬 조회 3회로
종료했습니다. 자동 재시도·교정·fallback은 0회였습니다. 외부 인터넷 검색·Discord·
영속 기억·학습·승격·active runtime 변경도 0입니다. P13C 평가 자료는 spent이며
재실행하거나 문항·답변·실패 출력을 학습 자료로 전환하지 않습니다.

## 3. Minecraft: 모델이 제안했는가, 실행기가 움직였는가

열린 일상 대화 대신 관측 가능한 작업으로 범위를 줄였습니다. Mineflayer 실행기와
frozen Actor를 연결하되, 모델의 계약 실패를 코드가 임의 이동으로 보정하지 않습니다.

| 계층 | 관찰 | 결론 |
| --- | --- | --- |
| 접속·실행기 | Minecraft 26.1 접속과 별도 goto 접근 확인 | 실행기 기능의 제한된 live 증거 |
| 모델의 도구 제안 | 실제 요청 2회 모두 `minecraft_goto`를 제안했지만 `reply`와 tool calls를 혼합 | 새 도구 계약 위반 |
| 외부 검증 | 계약 거부 `2/2`, 이동 실행 `0/2` | 두 요청에서 잘못된 계약이 실제 이동으로 이어지지 않음 |
| 채집 | 원목 인벤토리 증가 미검증 | 채집 성공을 주장하지 않음 |

이 두 요청은 탐색적 live 관찰이며 고정 평가 세트나 일반화 성능 측정이 아닙니다.
도구 이름을 출력했다는 것만으로 모델이 도구 계약을 이해했다고 보지 않습니다.
또한 별도로 실행한 goto 성공을 모델이 스스로 이동을 결정한 성공으로 합산하지
않습니다. 관찰 종료 후 해당 모델·봇 세션은 사용자 요청으로 종료했습니다.

## 다음 검증 관문

1. 모델 없이 이동→채굴→아이템 회수 실행기를 분리 검증합니다. 성공은 채굴 메시지가
   아니라 시작 대비 원목 인벤토리 증가로 판정하고, 기존 드롭 회수와 직접 채굴을 구별합니다.
2. 새로운 수동 평가 문항으로 frozen Actor의 도구 계약 준수를 확인합니다. 필요 없는
   이동, 대상 부재, 거부·취소도 포함하고 재시도나 코드의 대체 선택으로 통과시키지 않습니다.
3. 마지막으로 모델 선택→외부 승인→실행→관측 결과를 같은 작업 기록에 연결합니다.
   요청·시간·행동 예산과 중지 조건을 둔 별도 승인 실험으로 진행합니다.

이는 계획이며 아직 통과 결과가 아닙니다. 기존 spent 평가 자료와 실패 출력은
새 학습 자료로 재활용하지 않습니다.
